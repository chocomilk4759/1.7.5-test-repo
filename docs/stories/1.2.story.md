# Story 1.2: 단위 변환

## Status

Review

## Story

**As a** 공업용 계산기를 쓰는 사람,

**I want** `convert(value, from, to)`가 길이, 압력, 온도의 같은 종류 단위 사이에서 값을 정해진 정의대로 바꾸고, `units(kind)`가 그 종류의 단위 기호를 정해진 순서로 돌려주며, 잘못된 입력에는 `ConversionError`를 던지기를,

**so that** 변환한 값을 믿고 쓸 수 있고, 틀린 단위나 있을 수 없는 온도가 조용히 틀린 값이 되지 않는다.

### 기술 제약

프로젝트 구조는 `docs/architecture.md#소스-트리`와 충돌하지 않는다. `src/units.js`와 `test/units.test.js`는 그 표에 이미 있는 자리다. Architecture에 없는 파일은 만들지 않는다.

Architecture에서 온 제약은 다음과 같다.

- 언어와 실행 환경은 ES 모듈과 Node.js 24다. 내장 모듈만 쓰고 외부 패키지는 쓰지 않는다. 테스트는 `node:test`와 `node:assert/strict`다(`docs/architecture.md#기술-구성`).
- 공개 함수는 순수 함수로 두고 입출력이나 전역 상태를 쓰지 않는다. 오류 클래스는 `Error`를 잇고 자기 모듈에서 내보낸다. `src/units.js`는 `src/engine.js`를 가져다 쓰지 않는다(`docs/architecture.md#설계-원칙`).

단위의 정의는 다음과 같다.

- `in`, `ft`, `bar`, `psi`와 온도 식은 D-2가 정한다. D-2가 관계를 정하지 않는 `mm`, `cm`, `km`, `kPa`, `MPa`는 SI 접두어(milli 1e-3, centi 1e-2, kilo 1e3, mega 1e6)를 쓴다(N-6).
- 절대 영도의 세 이름은 0 K, -273.15 C, -459.67 F다. D-2의 식을 10진수로 손 계산하면 -273.15 × 9 / 5 + 32 = -491.67 + 32 = -459.67이다.
- AC 3의 목록에 음수 길이와 음수 압력이 없고 AC 1은 값을 돌려준다고 하므로 이 값들은 변환한다(N-6).
- 글자가 아닌 단위와 종류는 AC 1, AC 4의 목록에 없으므로 모르는 단위와 모르는 종류다(N-6).

구현할 때 놓치기 쉬운 점은 다음과 같다.

- 같은 단위 사이의 변환도 검사를 건너뛰지 않는다. `convert(-1, "K", "K")`, `convert(NaN, "m", "m")`, `convert(1, "x", "x")`는 던진다.
- 값의 판정에 전역 `isFinite`를 쓰면 글자와 `null`이 통과한다. `isFinite("5")`는 `true`이고, `null * 100`은 0, `"5" * 100`은 500이다. D-2는 number 형만 받는다.
- 기호를 보통 객체에서 찾으면 `constructor`, `toString`, `__proto__`가 찾아지고, 배열 `["m"]`은 글자 `m`으로 바뀌어 찾아진다. 어떤 자료 구조를 쓰든 이 입력은 모르는 단위이고, `units(kind)`에서는 모르는 종류다.
- `units`가 모듈 안의 배열을 그대로 돌려주면 호출자가 바꾼 내용이 다음 호출에 남아 설계 원칙의 "전역 상태를 쓰지 않는다"에 어긋난다. 복사본을 돌려줄지 얼린 배열을 돌려줄지는 구현 선택이다.
- `src/units.js`는 아무것도 가져오지 않는다. 변환은 산술뿐이어서 내장 모듈도 쓸 일이 없고, 1.2-INSP-001은 `node:` 가져오기까지 실패로 친다.
- 검사 순서는 정하지 않는다. 문제가 여럿인 입력도 모두 `ConversionError`이므로 합격 판정이 같다.
- 오류 메시지의 낱말과 언어, `ConversionError`의 `name`은 수용된 문서에 없어 시험하지 않는다(N-5). 메시지에 추적 번호를 넣지 않는 것은 아래 규칙대로다.

Draft 때 Node.js v24.22.1에서 계산한 배정밀도 값은 다음과 같다. 온도 경계와 시험 입력을 고른 근거이며, Dev는 구현 전에 다시 확인한다.

- 계산 순서가 경계 판정을 바꾼다. `(-459.67 - 32) * 5 / 9 + 273.15`와 `(-459.67 - 32) / 1.8 + 273.15`는 0이지만, `(-459.67 - 32) * (5 / 9) + 273.15`는 -5.684341886080802e-14다. 마지막 순서는 정확히 0 K인 입력을 절대 영도 아래로 만든다.
- `-273.15 * 9 / 5 + 32`는 -459.66999999999996이다. 이 값을 `F`의 경계로 삼으면 -459.67이 거부된다.
- `-459.67000000000007`과 `-273.15000000000003`은 각각 -459.67과 -273.15 바로 아래의 배정밀도 수다. `(-459.67000000000007 - 32) * 5 / 9 + 273.15`와 `-273.15000000000003 + 273.15`는 모두 -5.684341886080802e-14로 0보다 작다.
