## DOC-001 dev-1.1의 "시험 파일의 문자" 문장

앞선 기록은 고쳐 쓰지 않고 이 기록에서 바로잡는다.

- 어느 문장인가: dev-1.1의 Cleaner 결과 절 끝의 문단 "Dev가 함께 한 정리"의 마지막 문장이다. 시험 파일의 문자 U+00B0(도 기호)을 이스케이프로 바꿔 파일을 ASCII로 유지했다는 뜻이다.
- 무엇이 틀렸나: 그 문장의 "이스케이프" 뒤 괄호 안 코드 스팬에도 이스케이프가 아니라 문자 U+00B0이 적혀 있다. 바이트로 확인하면 앞뒤 두 코드 스팬이 모두 UTF-8 바이트 `c2 b0`(U+00B0)이다. 앞선 Dev 세션의 쓰기 도구가 입력의 이스케이프를 문자로 바꿔 저장했기 때문이다(Dev 질문 4, QA 라운드 1의 리드 10과 같은 도구의 성질).
- 사실: 시험 파일의 목록에서 `degC` 바로 앞의 값은 큰따옴표 안에 역슬래시, 소문자 u, 숫자 00b0, 대문자 C가 이어진 글자다(`grep -o`의 결과를 `od -c`로 본 바이트: 역슬래시, `u`, `0`, `0`, `b`, `0`, `C`). 이 이스케이프가 U+00B0을 나타내고, `LC_ALL=C grep -c '[^ -~]'`로 센 시험 파일의 ASCII 밖 바이트는 0이다. 그래서 dev-1.1의 사실(시험 파일이 ASCII이고 이스케이프가 남아 있음)은 맞고, 문장의 표현만 부정확했다.
- 이 기록: 이 기록 문서와 Story를 쓰는 도구도 같은 성질을 가질 수 있어, 이스케이프를 글자로 풀어 쓰고(역슬래시, 소문자 u, 숫자) 저장한 뒤 바이트로 U+00B0이 없음을 확인했다(아래 점검).

## DOC-002 Dev Notes의 "Dev는 구현 전에 다시 확인한다"에 대응하는 기록

- 확인: Story의 Dev Notes는 "Draft 때 Node.js v24.22.1에서 계산한 배정밀도 값"을 든 문단 끝에 "Dev는 구현 전에 다시 확인한다"고 적는다. SubTask 1.1의 기록(dev-1.1, dev-2.1, dev-dod-1)과 Completion Notes를 "다시 확인", "재확인", "다시 실행", 그 값(-459.66999999999996, -5.684341886080802e-14)으로 검색했고, 구현 전에 이 값을 다시 실행했다는 기록을 찾지 못했다. 그 값들은 dev-1.1에서 구현 뒤의 틀린 변형 점검 표에만 나온다.
- 사실로 적는 것: SubTask 1.1에는 구현 전 재확인의 기록이 없다. 이 세션은 앞선 Dev 세션이 그것을 했는지 아닌지를 알 수 없으므로 "했다는 기록이 없다"로 적는다. 빠진 증거는 뒤에 만들지 않는다.
- 이 값들을 이후에 다시 실행한 기록: QA 라운드 1이 Dev Notes의 값 여덟 개를 다시 실행해 모두 같음을 확인했다(qa-r1). 이 QA 수정 1회차의 단위 3.1이 온도 식을 바꾸기 전에 같은 값 여덟 개와 "바로 아래의 배정밀도 수" 둘을 다시 실행해 모두 같음을 확인했다([dev-3.1](dev-3.1.md)). 이 두 번의 실행은 SubTask 1.1의 구현 전 확인을 대신하지 않는다.
- 영향: 값이 환경에 따라 달랐다면 구현 전에 알지 못했을 위험이 있었다. 환경(Node.js v24.22.1)이 Draft 때와 같고 후속 실행 두 번이 모두 같은 값을 얻어 이 환경에서는 실제 영향이 없었다.
